## Product and implementation defaults

- This is duration trimming, not changing the frame dimensions or aspect ratio. UI label may say Crop video to match the user's terminology, but show start/end times and selected duration clearly.
- C opens the editor only for a current video in review or enlarged review. Add a visible button for discoverability and mobile use. Closing or canceling returns to the same original at its prior playback position. Desktop keys must not leak into keep/remove shortcuts while editing.
- Timeline: large draggable start and end handles, readable time labels, independent playhead scrubbing, preview frames when feasible, and playback between the boundaries. Dragging pauses playback and seeks to that handle. Resume only if it was previously playing. On release, clamp the playhead inside the selection; playback wraps to the selected start at the right boundary. Use pointer capture/cancel handling and touch-safe hit targets. A second pointer must not unexpectedly approve or move another handle.
- Minimum segment length: 0.5 seconds, or the full duration for a video shorter than 0.5 seconds. Disable approval for an unchanged full-range selection, unknown duration, invalid range, or an operation already in progress. Frame precision should be one frame or better where supported, with explicit tests. No silent export of a different segment.
- Keep original resolution, orientation, audio, frame rate, and HDR when supported. Prefer passthrough if it respects the requested boundaries. If exact trimming requires encoding, preserve these properties and report unsupported formats rather than silently degrading HDR or stripping audio. A new crop must not create an upscale or a needless quality conversion.
- Preserve the original capture timestamp, timezone when available, and location before upload, then verify the uploaded metadata. Missing metadata stays missing; never invent a location. A preservation or verification failure leaves the original decision unchanged and exposes a recovery path. Editing capture time/place in Google Photos might require a separate private API operation if it cannot be conveyed in the file; do not claim that unimplemented operations succeeded.
- Treat upload completion and video readiness separately. Save the replacement's exact identity and its provisional exclusion as soon as creation is acknowledged, before processing completes. This prevents concurrent imports from briefly showing it in review. Only after readiness, intended duration, decoded dimensions, playback and metadata pass verification may the original become a removal candidate.
- Match by account and exact original/replacement IDs, with file digest and job identity for retries. Two existing IMG_1130.MOV items have different IDs and lengths. Never delete, overwrite, or queue something merely because its filename matches. If a response is ambiguous after an upload, reconcile the existing upload/job identity before retrying. Do not automatically issue another upload that could duplicate the copy.
- Use one active export/upload job at a time for this personal desktop version; lock the source against conflicting decisions. Jobs survive page reloads and server restarts. Expired authentication, closed Google tabs, network interruptions, account changes, insufficient disk space, oversized files and export errors retain recoverable progress and the original's prior decision.
- Keep a local job directory private. Cap downloads and temporary disk usage, stream large files, and clean successful scratch downloads/exports after verification and a short recovery window. Retain failed job artifacts only when needed to resume, with an explicit cleanup action. Avoid long-lived copies of full videos or Google auth cookies in the backend.
- Preserve the existing local app authentication. OAuth app uploads require appendonly and read-only app-created media access for verification, not broad unrelated Google scopes. Store refresh credentials privately on the local host; do not send them into frontend code or logs. Use account binding, CSRF state, and PKCE/appropriate confidential-client validation.
- After crop completion, keep enlarged mode open and move to the next eligible original. Show a clear success message/link. The replacement is kept rather than appearing as the next swipe. Cancel/error does not advance the review queue. Undo of the queue decision must never delete the uploaded replacement; describe its effect clearly.
- No deployment, personal-site integration, or live user-photo deletion is authorized for the overnight run. Synthetic clips may be used for tests, and the explicitly authorized IMG_1130.MOV may produce a clearly labeled test copy. If broader permissions or credentials are unavailable, complete all independent work and report precisely what remains unverified.
