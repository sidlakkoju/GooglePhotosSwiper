# Video trim implementation handoff

Requested behavior: C on a video opens an iOS-style segment editor. Dragging either boundary seeks the preview to that boundary. Playback loops inside the selection. Approving creates a new clip, uploads it, verifies its playback and metadata, then marks the exact original as an unsent removal-album candidate. No Google Photos deletion is authorized or required.

Status updated October 6: local editor, native exporter, durable jobs/exclusions and optional official upload provider are wired into the app. Live browser-session transport research and complete Google Photos verification remain blocked by the locked Mac and absent OAuth setup. See [video-trim-status.md](video-trim-status.md) for current evidence and remaining work; the earlier sequence below is retained as planning history.

## Implementation sequence

1. Add a trim dialog and module. Use explicit start/end sliders and a timeline playhead with large touch handles. Arrow keys while a handle is focused adjust its boundary; Space toggles selected-segment playback; Escape cancels. Pause while dragging, seek continuously to the manipulated boundary, and resume only if playback was running before the drag. At release, selected playback wraps to the start when outside the interval. Video frame/time precision needs tolerance and clamping. Never let this dialog's keyboard events trigger review decisions.
2. Add persistent trim jobs in SQLite, account-bound and revision-checked. Stages: preparing, exporting, uploading, processing, verifying, completed, failed. Store the original media ID, start/end, source metadata, file digest, upload session/token, replacement IDs, and confirmation checkpoints. Lock only that original while a job is active. A retry must resume confirmed progress, not blindly upload twice.
3. Download the actual stored video through the Google Photos bridge; player previews are inadequate as an editing source. GetDownloadToken uses yCLA7 and CheckDownloadToken uses dnv2s in the researched web client. Keep cookies and Google page tokens in Chrome. Authorize exact IDs/account; do not fetch arbitrary caller-supplied URLs or copy cookies to the backend. Limit file size, disk use, duration, concurrency, and cancel stale work.
4. Export locally with AVFoundation on this Mac, preserving orientation, audio, capture time/timezone and GPS. The research passthrough export preserved location but lost capture time. Make the date explicit in the output metadata and compare Google Photos metadata after upload. Frame-accurate boundaries may require re-encoding rather than passthrough. Preserve originals and generated files through interrupted jobs until upload verification succeeds.
5. Configure official Library API upload credentials and consent. Upload resumably, persist upload token, create the new item, poll until READY, and verify playback, selected duration, dimensions and metadata. User was asked whether an OAuth client already exists; do not assume credentials or grants. The existing private bridge has no verified upload method. An automated browser upload was proven in the experiment, but is not a finished application upload API.
6. Only after verification: transactionally record the replacement as generated/kept (or excluded), mark the original remove, and complete the job. Match exact media IDs, not filenames. Import must consult replacement exclusions so the new clip does not appear next or reappear after refresh/restart. If a user later wants to review replacements, provide an explicit action. Preserve the original's previous decision for cancel/recovery; do not clear unrelated queue items. An existing album acknowledgement must not suppress the newly queued original. Default behavior marks it unsent for the removal album, rather than automatically sending the entire queue.
7. Keep the enlarged review viewer open and advance to the next eligible item after success. Cancel restores the original playback/review position. Upload/export errors leave the original unchanged and expose a resumable job with truthful status. Warn on pending jobs during sign-out without losing progress; wrong-account connections cannot resume.
8. Validate locally with synthetic clips, then the explicitly authorized IMG_1130.MOV without deleting it. Verify both desktop and mobile-responsive editor behavior, rapid handle movements, short videos, full-range no-op, invalid metadata/duration, network failures, duplicate approval, restart/retry, matching filenames, concurrent imports and decisions, rotated/HDR media, and missing original files.
